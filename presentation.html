Граф экранов — как игра переходит между сценами

ValmerionGame │ game.setScreen(...) │ ┌──────┴──────────────────────────────────────────────────────────┐ │ │ ▼ ▼ MenuScreen CutsceneScreen │ "Новая игра" (слайды с субтитрами) │ │ │ ▼ │ ClassSelectionScreen │ (лучник / маг / воин) │ │ │ "Продолжить" │ └──────────────────────────────────────────────────────────────────┤ ▼ WorldScreen storyStage = 0 или 2 / \ ▼ ▼ AcademyScreen CongratulatoryScreen storyStage = 1 storyStage = 3

Правило

Каждый экран — отдельный класс. game.setScreen() уничтожает старый экран и запускает новый. Состояние хранится в GameState, не в экранах.

BaseScreen

Все экраны наследуют BaseScreen — он содержит общие объекты: batch, viewport, assets. Каждый экран реализует только render() и dispose().

[Continue в меню] ──► stage==1 → Academy │ stage>=3 → Credits │ иначе → World

Почему целое число, а не enum?

Проще сериализовать в SharedPreferences и сравнивать (stage >= 3). При добавлении новых актов — просто добавляется следующее число. Enum потребовал бы маппинга при сохранении.

Сохранение прогресса

GameState.INSTANCE (singleton, загружается при старте) ├── storyStage : int ← где находится история ├── selectedClass : String ← "archer" / "mage" / "warrior" ├── hp : float ├── hunger : float ← убывает со временем ├── reputation : float └── gameStarted : boolean ← показывать кнопку "Продолжить"? save(): Gdx.app.getPreferences("valmerion_save") │ ├── Android → SharedPreferences (XML в /data/data/...) └── Desktop → ~/.prefs/valmerion_save Когда сохраняется: • После разговора с Заком → stage 0→1 • После прохождения Академии → stage 1→2 • После разговора с Хенкаем → stage 2→3 • При выходе в главное меню → текущее состояние load(): Вызывается один раз при старте ValmerionGame Если файла нет → все значения по умолчанию (stage=0)

Почему не файловая система?

Preferences — кросс-платформенный API LibGDX. На Android это нативный SharedPreferences, на Desktop — файл в домашней папке. Не нужно думать о путях, правах доступа и форматах — всё делает LibGDX.

А что если... — вопросы и ответы (1/2)

❓ Что если игрок упадёт за нижний край экрана?
Не упадёт. В Player и Goblin жёсткий ограничитель:
if (y ≤ 128) { y = 128; vy = 0; }
Земля — это не физический объект, а просто проверка числа каждый кадр.
❓ Что если убить гоблина в момент его атаки — урон всё равно пройдёт?
Зависит от момента. Урон наносится на attackTimer = 0.18с. Если гоблин умирает от стрелы в 0.17с — урона нет. В 0.19с — уже прошёл. Стандартное поведение для игр такого рода.
❓ Что если нажать атаку пока летит стрела — можно спамить?
Нет. Флаг attacking == true блокирует новую атаку на 0.35с. Стрела выпускается при нажатии — одна стрела на одно нажатие, без возможности спама.
❓ Что если закрыть приложение во время Академии — прогресс сохранится?
Частично. storyStage=1 сохраняется до старта Академии. Но прогресс внутри (какой этап пройден) не сохраняется — обучение начнётся заново. Это нормально для короткого туториала.

А что если... — вопросы и ответы (2/2)

❓ Что если гоблин умирает но анимация не проигрывает?
alive = false сразу при hp ≤ 0. В Goblin.update():
if (!alive) { setState(DEAD); return; }
Гоблин замирает в анимации смерти. Движение и атаки прекращаются мгновенно.
❓ Что если сделать displayScale = 10 — гоблин вылезет за экран?
Да. Спрайт рисуется от drawX = x + (48 − dw) / 2. При scale=10: dw=960, drawX = x − 456 — гоблин уйдёт за левый край. Ограничения нет, масштаб предполагается разумным (1–3×).
❓ Что если два гоблина атакуют одновременно — это возможно?
В текущем коде нет. AcademyScreen держит одну переменную goblin. Сначала STATIC, после гибели — AGGRESSIVE. Два гоблина одновременно невозможны без рефакторинга в список.
❓ Что если атака ближнего боя попадёт по гоблину несколько раз за свинг?
Раньше именно так и было — гоблин умирал с 1 удара! Исправлено флагом meleeHitLanded: после первого попадания getAttackHitbox() возвращает null до конца анимации.
